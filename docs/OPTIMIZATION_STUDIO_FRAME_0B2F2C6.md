## Production changes and ownership

| Package | Finding and change | Equivalence and safety boundary | Operation effect |
| --- | --- | --- | --- |
| A1 — selection ownership | `StudioPoseEvaluator::evaluate` selected body/skin into `const` result objects, so `std::move` still copied vectors. `src/goldsrc/studio/goldsrc_studio_pose.cpp` now retains non-const selector results and moves their selections into the pose. Compose also moves its final selections rather than copying through const accessors. | Source selection objects are not read after move. The `[selection-ownership]` test exercises the same body/skin combinations and rejections. | Removes two selection-vector copies per normal retained pose; this is an operation claim, not a whole-game speedup. |
| A2 — viewmodel pose | `RuntimeReplayLocalAssets::materialize_viewmodel` already evaluated a pose; same-frame attachment lookup independently evaluated it again. `src/app/runtime_replay_local_assets.cpp` and the matching header retain the successful pose and exact `ViewmodelIntent` for frame-local reuse. | Cache use requires complete intent equality and the identical frame coordinate. Historical-frame requests still evaluate independently. Start/failure of materialization and successful generation reset invalidate pose and attachment-zero state; attachment-zero publishes only after the complete frame succeeds. Camera-local origin remains applied when resolving the attachment. | The normal materialize + same-frame attachment path uses one full evaluation instead of two. |
| A3 — visual summary | `project_entities` deep-copied the entire public summary each frame before clearing dynamic maps. It now stages into a second owning summary, copies immutable resource metadata once at creation, accumulates enum coverage in a fixed indexed array and model-slot counts in a sorted sparse vector, and forms the public maps only at publication. | The staged summary is not the published object. Render-frame/target success precedes a no-throw pointer swap; failure retains the committed summary. Unbound diagnostic slots, remote-player tail, counters, resource issues and omission semantics remain represented. The two owning objects persist for the local asset context; they are not a cross-session cache. | Removes per-frame deep copy of resource names/issues. Capacity and allocation deltas require measured instrumentation; no fabricated allocation count is given. |
| B — local Studio sampling | `compose` previously called full `evaluate` for main/previous/layer and rebuilt the final hierarchy, including a redundant build for main-only. A shared internal local sampler now handles the public `evaluate` path and the compose inputs; compose builds the final world hierarchy once on the ordinary valid path. | Shared frame/blend/controller/motion logic is retained. Hierarchy and finite-local validation run for every sampled layer, including masked/zero-weight layers. Extreme finite translations take the old full-world validation path so hidden overflow is not newly accepted. The old admission-budget `accounted_pose_bytes` and output-size `world_matrix_count` keep their contracts; new `world_build_calls_v2`, `world_matrices_built_v2`, and bounded `retained_pose_vector_capacity_bytes_v2` report actual work and retained-vector capacity separately. | Normal main-only: 2 world builds to 1. Normal main+previous+layer: 4 to 1. Extreme-input validation can legitimately perform additional builds. This does not imply a 2×/4× total frame speedup. |
| C — immutable snapshot lookup | Repeated linear entity searches traversed immutable packet snapshots and repeated ordinary/player candidate eligibility scans at each render. `src/app/runtime_replay_local_assets.cpp` now uses exact `lower_bound` lookups in validated, strictly sorted snapshots. Source-owned, sorted candidate-number vectors are staged with a new authoritative observation and committed together with its owner; `present_entities` reuses only those lists for unchanged source revisions. | `src/client/runtime_observation.cpp` validates strict ascending unique entity numbers before ownership is accepted. Candidate lists hold numeric IDs, not iterators or pointers to evictable history; every use resolves against the current owner. Per-render receiving slot, game-module `world_entity` decisions, source/alpha/time/support sampling, visibility, and model readiness remain dynamic. `world_entity` policy/side-effect invariance was not proved, so its P×H decisions were **not** cached. `project_entities` still iterates the presented entities every render. | Exact lookup changes from linear scan to binary search. Candidate-list classification moves from every render to accepted-source staging. Whole-frame entity iteration and continuity policy traversal remain; neither is claimed eliminated. |
| D1 — two diagnostic rays | For each action, view and command rays each located the same model and recomputed hitbox transforms/inverses. `src/app/multiplayer_presentation_diagnostics.cpp` prepares bounded hitbox geometry once per action and runs independent ray intersections. The source-asset lookup cache is tied to a retained `shared_ptr` package owner, not a reusable numeric revision. | Per-ray origin, direction, nearest hit, obstruction, completeness and output identity remain independent. Source-probe, actor and box budgets still bound the query. A stale/missing/singular/exhausted proxy remains unknown/incomplete, never an authoritative hit or miss. Diagnostics Off does not invoke this work. | Two full proxy preparations per eligible action become one; there are still two ray intersection passes and independent world queries. |
| D2 — F8 membership | F8 compared up to 1,280 recent entries against up to 512 protected exact events with nested scans. `src/app/multiplayer_timeline.cpp` now builds a bounded, sorted 512-key index and performs binary membership tests. | The key contains exactly producer, producer event ID, network generation and map generation, matching the old identity comparison. Keys are stored in already heap-owned timeline storage, not a large Win32 stack temporary. A protected event omitted from the 64-event manual window is still excluded as a recent duplicate, preserving omission accounting and priority/order rules. | Replaces the O(recent×protected) membership scan with bounded sort plus O(recent log protected) lookups; event collection/publication remains bounded and otherwise unchanged. |
