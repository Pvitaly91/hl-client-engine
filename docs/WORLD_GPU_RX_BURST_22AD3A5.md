# HLC-22AD3A5: world GPU та RX burst

Цей пакет продовжує normal `hlclient.exe` з `main` на перевіреному початковому HEAD `22ad3a5bf98ff5213ea8e6992d94d07fe9a9a130`. Робота виконана офлайн: нових ігрових, Steam або HLDS-сесій агент не запускав. Ручне приймання нової збірки до звіту користувача — `not_run`.

Локальні копії — в `%LOCALAPPDATA%\HLClientEngine\runs\<run_id>`. Архіви не містять EXE; наведений у них SHA клієнта `F84AE4973760C0BC6FCD813843247562A4CBAA4C0F6596346FED2E504AD874C7` є твердженням звіту. Окремо перед змінами захешовано фактичний source та доставлений `hlclient.exe`: обидва збігалися з цим SHA, 5 530 624 bytes. Launcher SHA — `5F3A4BDDEE4DCE1D051CC418BF876405369A83016EFFFE3E12D8528F4142466C`.

В обох запусках — Crossfire, 1920×1080 borderless, VSync On, 144 Hz у reported display mode, diagnostics On; launch-config різниться тільки `msaa_samples` 0/8. Повна controlled-alive когорта дає FPS-equivalent `143.0647` проти `116.8670`; це різні матчі й камери, а не same-scene ціна MSAA. Збережені F8 GPU-виміри проріджені: у 8× `world` mean `6.7637 ms`, GPU total `8.4147 ms`, resolve `0.8216 ms`, image adjustment `0.4448 ms`. На frame 3538 `world=10.065276 ms` з `GPU total=11.700052 ms`; CPU update `2.7844 ms`. Не можна додавати CPU/GPU/inclusive інтервали чи називати GPU timestamp безпосередньо shader-busy time. Не доведено пересоздання MSAA target кожного кадру: actual 8× повний, fallback none, allocation 1/release 0.

Для мережевого епізоду 8×: між frame 3128 (source 523) і 3208 новий coherent source не просувався; frame 3209 прийняв source 524, frame 3210 — source 532, вісім committed records/8 569 bytes, 26 replayed commands. У frame 3210 frame interval `34.5232 ms`, CPU update `32.928 ms`, parse/commit `17.7353 ms`, prediction `6.0583 ms`. `replay_duration=520 ms` — симульований командний проміжок, не CPU-час. Джерело upstream паузи невідоме. У config записано target `5.231.120.14:27017`, у console-attempt — requested `192.168.0.104:27016`; жодне з цих полів окремо не є UDP packet capture або доказом peer виміряної гри.

Передані `REPORT_UK.md`, `comparison_evidence.json`, `source_excerpts.txt` для саме цих двох запусків локально не були доступні; знайдені однойменні файли в Downloads старіші й стосуються інших епізодів, тому не підміняють ці архіви. Похідні висновки спираються на точні run IDs, їхні JSON, поточні контракти та локальні offline fixtures.

## Контрольований метод

Перед правками перевірено source root/branch/HEAD/чистий tracked стан та CMake Win32/Release cache. Збережено `git archive HEAD`, початкові Release client/tests EXE, CMake cache і чинні доставлені client/launcher EXE у `manual-artifacts/task-records/world-gpu-rx-burst-22ad3a5-20261020`. Чисте baseline production source з test-only harness позначається окремо; жоден тестовий harness не є production-правкою baseline. Ресурси Half-Life/Crossfire лише читалися з `D:\DEV\HLCLIENT-RESEARCH\Half-Life`.

GPU-контроль використовує існуючий hidden OpenGL actual-assets fixture, фіксовані час/анімацію/геометрію/акторів, 48 warm-up і 192 timed samples, без swap. Камери з frame 3538 і F8 marker відтворюють лише `eye` та final yaw/pitch через той самий production `forward_from_yaw_pitch`; відсутні історичні позиції ботів, effects і lights лишаються явно synthetic/fixed. Baseline↔candidate порівнюються за однакового MSAA й того самого harness; AA Off — окремий regression control. Колір порівнюється signature. Початковий full-frame Off depth hash виявився переважно depth viewmodel після його clear, тому як oracle світу не використовується: після timed loop окремо рендериться та сама static-world camera і читається її Off depth з nonclear-pixel контролем. Для 8× depth міститься в приватному multisample FBO, тож default-depth signature не видається за дійсний; там діють окремі masked/depth controls.

RX-контроль — синтетичне механічне відтворення паузи, восьми впорядкованих records з 78 entities, двома `svc_sound` посеред burst та окремого 26-command matched-boundary suffix. Це не raw-wire replay архівної сесії. Fixture перевіряє кожний record, обидві звукові події в порядку та canonical state; інші gameplay/lifecycle межі перевіряються окремими регресіями й не приписуються цьому fixture. Різні допустимі batches не зобов’язані мати однакові намальовані проміжні кадри.

## Атестація P1 branch/copy

`ExternalP1BranchObservation::observe` бере вже наявні накопичувальні лічильники `direct_adjustment_frames`, `output_color_blits`, `resolved_texture_reads` і `framebuffer_copies` після завершеного виклику renderer. `encode` додає їх у фінальні video й movement receipts, а не в щокадровий текст. Scope — один екземпляр `OpenGlRenderer` у межах однієї спроби застосунку; спад лічильника відкриває нову reset epoch. Для зміни Off→8×→Off, resize, capability або network/map generation записуються обмежені 16 режимних сегментів, а при перевищенні бюджетів звіту вказується пропуск сегментів. До першого фактичного спостереження значення — `unknown`, а не нулі.

Джерело `cached_default_back_output_compatible` — чинна одноразова перевірка scene target. Нового capability scan, синхронного запису на кожному кадрі або зміни перевіреного P1 fast path немає. Ці counters не входять до revision key публікації. Офлайн-тест перевірив атрибуцію режимів, reset, reconnect і publication-budget fallback; він не підміняє собою вимір фактичної гілки в майбутній грі. Альтернатива визначати гілку за одним лише часом image-adjustment відкинута як непряма й неоднозначна.

## W: world GPU і повторні GL-прив’язки

У `OpenGlRenderer::render` збережено початковий aggregate `world` і додано чотири асинхронні підінтервали: target setup/clear, sky, static-world command section і окремий runtime-brush loop. Вони прив’язані до source frame та мають окрему valid mask: pending/unsupported/disjoint не перетворюються на нуль. Профіль фіксованої MSAA 8× сцени frame3538 показав, що всередині world домінує visible-command section (candidate p95 близько `4.031 ms`; sky близько `0.549 ms`, setup/runtime близько `0.001 ms` кожен). Цей section може містити selected brush-instance draws разом зі стінами; його час не є чистим часом статичної геометрії. Початковий baseline не мав цих підтаймерів, тому окремі baseline↔candidate subpass speedup не заявляються.

У `draw_package_range` прибрано повторні `glBindTexture` і material-uniform uploads, коли наступний draw використовує той самий фактичний GL texture name та значення параметрів. Кеш живе лише в одному суміжному world draw section; зміна resources/program його скидає, активний texture unit після section відновлюється. Порядок draw, геометрія, PVS, матеріали та MSAA не змінені. Відхилено агресивне сортування/злиття поверхонь або пропуск видимості: причин для цих ризикових змін вимір не дав.

Основна фінальна серія — 8 окремих exit-0 Win32 Release запусків: baseline/candidate × два фіксовані ракурси × MSAA Off/8×; по 192 non-capture timed frames на кожну умову після 48 warm-up. Це один B/C процес на кожну комбінацію ракурсу й MSAA; додатковий sensitivity repeat мав змінений harness і не об'єднувався з фінальною серією. У MSAA 8× F8-ракурсі базових texture binds за 192 кадри стало `5952→1728`, lightmap `5952→576`; у frame3538 `32064→3840` та `32064→576`. Draws і triangles незмінні. Колір збігся B/C у всіх чотирьох умовах, а ізольований world-depth — B/C для обох Off-ракурсів. Але GPU world p95 змішаний: F8 8× `3.071→3.142 ms` (+2.3%), frame3538 8× `4.828→4.581 ms` (−5.1%); Off — практично без виграшу. CPU render-submit p95 також змішаний. Отже статус W — **операції зменшені, загальний time speedup не встановлений**; це не обіцянка приросту FPS у грі. Вимірювач викликав GPU timing і `glFlush`; окремого diagnostics-Off B/C для W немає, тому інструментаційний overhead не відокремлений. Memory high-water не вимірювався, а present interval до hidden/no-swap fixture не застосовується; ліміт запитів — 8 одночасних aggregate slots по 16 timestamp boundaries. Сирі samples, SHA логів/EXE, точні argv, invalid/drop counts і додатковий sensitivity repeat — у локальному `manual-artifacts/task-records/world-gpu-rx-burst-22ad3a5-20261020/w-benchmark-manifest.md`.

## N: післяпаузний RX burst

`RuntimeReplaySession` уже перевіряє кожен `DeltaObjectState` проти повного immutable schema перед semantic projection. У восьми місцях projection після знаходження definition додатково лінійно шукав його value через `object.find_exact`. `field_at_validated_index` бере value за підтвердженим wire index з локальною перевіркою bounds/index/name; попередні descriptor/type/finite/error перевірки лишилися. Це прибирає зайвий другий structural scan, не змінюючи decode, порядок транзакцій, події, ACK чи 26-command replay. Відкладати проміжні commits або «стискати» burst до останнього snapshot відкинуто, бо це загубило б події й lifecycle межі. Додатковий schema-index cache не додано: його вартість та коректні generation keys не доведені.

Порівняння — pre-N GPU-виправлена збірка проти тієї самої збірки з однією N-правкою, з однаковим test-only fixture. Синтетичні 78 entities, один untimed seed, 8 ordered records після змодельованої 500 мс паузи та два `svc_sound` дають однаковий canonical hash `15026093827131519465`; diagnostic sink On бачить обидві події. Окремий matched-boundary тест точно відтворює suffix із 26 команд. П’ять чергованих запусків у кожному Off/On режимі дали по 400 timed bursts на версію: Off p50 `3085.2→3033.3 µs`, p95 `3576.9→4238.7 µs`; On p50 `3097.6→3017.6 µs`, p95 `3443.7→3916.3 µs`. Гірший кандидатний хвіст зосереджений в окремих запусках 02/03, а інші близькі або кращі; стабільний speedup чи регресію не встановлено. Це суми восьми `apply_record` викликів, не час повного ігрового кадру і не частка архівного `17.7353 ms` parse/commit. Allocation/copy reduction і memory high-water окремо не вимірювалися. Висновок N — **повторні scans прибрано; часовий виграш не доведений; причина upstream паузи невідома**.

Окремо пройшли runtime-replay, reconciliation, slot-reuse і sound-owner регресії. Сам timed burst не містить DeathMsg/respawn, projectile або кількох shots, тож їхню збереженість підтверджують лише відповідні окремі контроли в обсязі, зазначеному в локальному `manual-artifacts/task-records/world-gpu-rx-burst-22ad3a5-20261020/n-benchmark-manifest.md`. Маніфест містить 20 raw log hashes, per-run p50/p95/p99/max, початкові невдалі спроби та межу відсутнього exact shell transcript.

## Фінальна офлайн-перевірка

Після останньої production-правки normal Win32 Release `hlclient.exe` зібрався; focused Release контролі W/P1, N і попередніх A–D/P1–P6 пройшли відповідно `52/678393`, `2/367` і `41/847802` test cases/assertions. Початковий повний CTest у sandbox був зупинений на початку #3136 із 4233, тож **не є повним вердиктом**: 2923 пройшли, 96 пропущено, 115 впали та один завершився вторинним SIGSEGV після невдалого запису receipt. У цьому середовищі `127.0.0.1` UDP send повертав 4 bytes, але receive спливав за timeout; також заборонялися тимчасові hardlink/junction та атомарні файлові операції. Ті самі два характерні unit-тести впали на збереженій baseline-збірці в тому самому sandbox, а поза ним кандидатні UDP, receipt, hardlink, junction і atomic-write sentinels пройшли. Це пояснює ці конкретні environmental failures, але не перетворює перерваний CTest на успіх.

Для повторного ширшого прогону відібрано 4229 із 4233 зареєстрованих Release-тестів. Чотири тести, що запускають окремий клієнт/UI (`hlclient_application_deferred_handshake_startup`, `hlclient_console_idle_no_assets_e33`, `hlclient_null_renderer_smoke`, `hlclient_external_launcher_ui_offline`), виключено за умовою нуля нових ігрових сесій. Unit/fake-peer тести з loopback і без live endpoint лишено. Усі 4229 вибраних CTest-статусів завершилися без падіння: 4154 `Passed`, 75 `Skipped`, 0 `Failed`, exit 0 за 484.68 s. Пропуски — здебільшого опціональні installed-assets/GPU/SDL, filesystem capability або opt-in probes; точний перелік у локальному `manual-artifacts/task-records/world-gpu-rx-burst-22ad3a5-20261020/final-verification-manifest.md`. Це **safe subset**, не повний виконаний набір 4233.

Для Debug створено окремий офлайн Win32 build із локальними залежностями. Початковий спільний `/Zi /FS` PDB викликав MSVC `C1902`; після переходу цього ізольованого build на embedded `/Z7` production-код зібрався. У тестовому helper Debug/Werror виявив недосяжний `return` після `if constexpr`; test-only виправлення додало `else` без зміни production-коду. Остаточна Debug-збірка й focused прогони W/P1 (`52` cases, `678393` assertions), N (`2/367`) та попередніх контролів (`41/847802`) завершилися exit 0. Фінальний Release safe subset вище запускався після останньої production-правки, але перед цим суто test-only `else`; на остаточному test source Release test-target перелінковано й усі три focused групи повторно пройшли з тими самими кількостями та exit 0. Окрема ASan конфігурація не запускалася.

В окремій офлайн Win32 Release конфігурації з `HLCLIENT_BUILD_GAME_HALFLIFE=OFF` і локальними залежностями core API зібрався, а `hlclient_core_api_offline` та `hlclient_game_boundary_guard` пройшли `2/2`, exit 0. Неігровий fake-fixture контракт запуску, `Start-HLClient-H2-Manual.ps1 -CheckOnly -SourceOnly` та `hlclient.exe --version` теж завершилися exit 0; `CheckOnly -SourceOnly` явно **не перевіряє** зовнішні файли гри/Steam і не означає успішного live-підключення. Чотири app/UI startup тести з safe subset лишилися невиконаними, ASan — `not_run`.

Launcher source обирає `hlclient.exe` поруч із власним EXE; його код і доставлений файл не змінювалися. Після перевірки відсутності запущених `hlclient`/`HLClientLauncher` попередній доставлений клієнт зі SHA-256 `F84AE4973760C0BC6FCD813843247562A4CBAA4C0F6596346FED2E504AD874C7` збережено в rollback-копії. Новий normal Win32 Release доставлено в чинний каталог launcher; source і delivery мають по `5 541 376` bytes та однаковий SHA-256 `F97074BF4BF1131A8AD48074F9330E0BB065A21C5B1517ED4D9081B4F776FA50`. Launcher SHA лишився `5F3A4BDDEE4DCE1D051CC418BF876405369A83016EFFFE3E12D8528F4142466C`. Staging/commit/push не виконувалися.

## Межі висновку

Пакет не змінює MSAA/роздільність, мережеві rate/ACK/horizon, prediction, сервер, Steam, stock assets чи ботів. Результат hidden/no-swap fixture не гарантує 100/144 FPS на реальному дисплеї. Окремий Off `movement_trace_failed` близько 91.91 s (`support_clearance/server_entity_box`) не належить до W/N і не позначається виправленим. Нижчий старий image-adjustment time не доводив P1 branch сам по собі; для цього експортуються його справжні branch/copy лічильники з явним scope та reset epoch.

Машинні виміри, точні команди/виходи та статус ручного приймання наведено в [evidence](evidence/WORLD_GPU_RX_BURST_22AD3A5.json) і локальних маніфестах. Ручний ігровий прогін цього Release агент не запускав.
