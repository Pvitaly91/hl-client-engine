# Єдиний пакет HL Client для Windows 10

Актуальний комплект — `dist/HLClientEngine-Win10.zip`, запуск — **HLClientLauncher.exe** у повністю розпакованій папці `HLClientEngine`. Це звичайний Windows-лаунчер із налаштуваннями відео, HUD, звуку та двома прапорцями діагностики. Варіант для гри й варіант для діагностики більше не розділяються.

`Start-HLClient.cmd`, PowerShell GUI, старі `HLClient-Portable-Win10*.zip` та архіви лише з оновленням логування виведені з актуального розповсюдження. Історичні скрипти в джерелах не включаються до нового ZIP.

## Синхронне оновлення обох ПК

Кожне виправлення доставляється одночасно в локальну збірку
`D:\DEV\CPP\HL-Client-engine\build\bin\Release` і мережеву
`\\192.168.0.104\storage\HLClient-Win10-Test`. Змінені виконувані файли мають
однакові SHA-256; portable-папка та ZIP відповідають тому самому кандидату.
Налаштування, шляхи ресурсів Half-Life і логи кожного ПК залишаються окремими.
Якщо один напрямок недоступний або EXE зайнятий, оновлення не оголошується
повністю доставленим. Старий шлях checkout не є актуальним локальним запуском.

## Запуск і логи

У секції «Відео» прапорець «Віконний режим» перемикає вікно та
повноекранний без рамки; новий профіль типовий повноекранний. Прапорець
«Показувати FPS» зберігається разом із налаштуваннями лаунчера. Він має
пріоритет над старим `cl_showfps` у `console.cfg` під час запуску, але
лічильником і далі можна керувати з консолі. `fps_max`, VSync і частота
симуляції цим прапорцем не змінюються. Старі профілі читаються без скидання;
після помилки відеорежиму/конфігурації зберігається безпечний віконний fallback.

Для прямого запуску та спільного доступу до журналів із SMB є тестовий
комплект `HLClient-Win10-Test`. Це той самий native лаунчер: фіксований
маркер `HLClientSharedTest.txt` з текстом `hlclient-shared-test-v1` вмикає
зберігання налаштувань, консолі, startup і runs у `test-data` поруч із EXE.
Папка розділена за ПК/користувачем; звичайний комплект без маркера зберігає
попередню поведінку LocalAppData. Обидві діагностики в тестовому комплекті
початково ввімкнені й доступні для вимкнення. Інструкція —
`packaging/windows10/SHARED_TEST_UK.txt`. Паролі SMB у файли не входять.

`scripts/package_windows_shared_test.ps1` приймає явний ReleaseDirectory і
свіжий OutputDirectory. Це кандидат із перебудованим клієнтом, без заяви
про попереднє ігрове прийняття. Виправлення UNC потрібне також усередині
клієнта для читання launch-config і публікації діагностики. SMB-серверу
потрібні права виконання EXE/DLL. `--offline-shared-storage-check` перевіряє
реальний запуск дочірнього клієнта з навмисною помилкою SDL та збереження
фатального повідомлення й системного ZIP без Steam/серверного підключення.

Розпакуйте весь архів у звичайну папку, запустіть Steam зі своєю ліцензійною Half-Life, відкрийте **HLClientLauncher.exe**, виберіть папку встановленої Half-Life та адресу сервера. SDL3 і потрібні x86 бібліотеки Visual C++ включені. Ігрові ресурси та `steam_api.dll` беруться з власної інсталяції Half-Life.

«Комплексна діагностика гри» та «Системна діагностика CPU/GPU» вмикають додаткові записи. Їх можна вимкнути в цьому самому вікні. Базові журнали запуску й причини помилки залишаються доступними незалежно від цих прапорців. Кнопка «Зберегти ZIP логів…» створює архів для передавання на інший ПК, «Папка логів запуску» відкриває журнали в Провіднику.

Журнали запуску: `%LOCALAPPDATA%\HLClientEngine\startup`, резервний шлях — `%TEMP%\HLClientEngine\startup`. Покрокові дії та вимоги до обладнання наведені в `packaging/windows10/START_HERE_UK.txt`; ця інструкція входить до комплекту. Налаштування та ігрові сесії залишаються в `%LOCALAPPDATA%\HLClientEngine`. Для FPS/prediction потрібна повна папка потрібного Run ID, а не лише `system-diagnostics.zip`.

## Пакування розробником

Пакувальник не компілює програму. Він отримує явну папку чотирьох Release-файлів: `HLClientLauncher.exe`, `hlclient.exe`, `SDL3.dll`, `HLClientSystemDiagnostics.exe`; перевіряє хеш прийнятого клієнта, залежності та app-local runtime, копіює за дозволеним списком і виконує офлайн-перевірки розпакованого комплекту.

```powershell
pwsh -NoProfile -File .\scripts\package_windows10_release.ps1 `
  -ReleaseDirectory C:\Path\To\VerifiedRelease
```

`scripts/build_portable_release.ps1` залишено лише як сумісне ім'я команди, що передає ті самі параметри цьому пакувальнику. Він не створює другого продукту й не збирає старий скриптовий лаунчер.

Результат завжди має одне ім'я: `dist/HLClientEngine-Win10.zip` і папка `dist/HLClientEngine`. Якщо вони вже існують, пакування зупиняється; попередній комплект потрібно спочатку зберегти до каталогу історії. Пакувальник самостійно не перезаписує старі файли чи налаштування.

Для зміненого лаунчера використовуйте `-LauncherRebuilt -LauncherChangeDescription 'опис зміни'`. Прийняття попередньої ігрової сесії підтверджує незмінений `hlclient.exe`, а новий лаунчер отримує окремий результат офлайн-перевірок. `BUILD_INFO.json` фіксує це розділення, точні хеші, залежності й обмеження перевірки. Пакування на машині розробника не є тестом фактичного запуску на Windows 10.
